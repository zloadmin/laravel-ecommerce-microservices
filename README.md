# Laravel E-commerce Microservices

An e-commerce REST API built as a set of independent Laravel services.

## Architecture

| Component | Path | Role |
|---|---|---|
| Gateway | `services/gateway` | Single public entry point: routing, rate limiting, correlation IDs |
| Auth | `services/auth` | Users, registration, login, JWT (RS256), refresh tokens |
| Catalog | `services/catalog` | Products and categories, filtering, cursor pagination |
| Orders | `services/orders` (planned) | Checkout and order lifecycle |
| Shared package | `packages/shared` | Cross-cutting infrastructure code only (error format, JWT verification, middleware) |

- **Database per service** (PostgreSQL): `auth`, `catalog`, `orders`. No cross-service joins.
- **Sync calls** go over REST; **domain events** go over RabbitMQ.
- Only the gateway is published to the host. Public paths map to services in
  `services/gateway/config/gateway.php` (`/api/v1/products` → catalog, and so on).
- **Authentication:** auth signs short-lived RS256 access tokens with a private key that only it holds.
  The gateway and every service verify them with the public key (`infra/keys`, generated by `make keys`),
  so no service calls auth at request time. Protect a route with the `jwt` and `role:admin` middleware.
- Every error uses one shape: `{"error": {"code", "message", "details"}}`.

## Getting started

Requires Docker with Compose.

```sh
make setup   # env files, image build, composer install, app keys, JWT keys, migrations
make seed    # optional: sample catalog, admin@example.com and customer@example.com (password "password")
make up      # start the stack
curl localhost:8080/api/v1/health
```

| What | Where |
|---|---|
| API (gateway) | http://localhost:8080 |
| RabbitMQ UI | http://localhost:15672 (ecommerce / secret) |
| PostgreSQL | localhost:54320 (ecommerce / secret) |
| Redis | localhost:63790 |

Host ports are set in `.env` (see `.env.example`).

## API

All paths are served by the gateway under `/api/v1`.

| Method | Path | Auth | Description |
|---|---|---|---|
| POST | `/auth/register` | none | Create a customer account, returns tokens |
| POST | `/auth/login` | none | Returns an access token and a refresh token |
| POST | `/auth/refresh` | refresh token | Rotates the refresh token (single-use) |
| POST | `/auth/logout` | refresh token | Revokes the refresh token |
| GET | `/users/me` | Bearer | Current user profile |
| PATCH | `/users/me` | Bearer | Update name or password |
| GET | `/categories`, `/categories/{id}` | none | List and view categories |
| POST, PATCH, DELETE | `/categories`, `/categories/{id}` | admin | Manage categories |
| GET | `/products` | none | List products (see filters below) |
| GET | `/products/{id-or-slug}` | none | View a product |
| POST, PATCH, DELETE | `/products`, `/products/{id}` | admin | Manage products |

Product list parameters: `q` (name or SKU), `category` (id or slug), `min_price`, `max_price`, `ids[]`,
`sort` (`newest`, `oldest`, `price`, `-price`, `name`, `-name`), `per_page` (max 100) and `cursor`
(from `meta.next_cursor`). Prices are integers in minor units: `{"amount": 129900, "currency": "USD"}`.
Guests and customers see only active products; admins see all.

## Common commands

```sh
make test s=gateway   # run one service's tests
make test-all
make migrate          # run migrations for all services
make sh s=gateway     # shell into a service container
make logs s=gateway
make pint s=gateway   # format code
make down
```
